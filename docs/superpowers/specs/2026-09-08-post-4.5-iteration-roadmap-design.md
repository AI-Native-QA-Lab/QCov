# 4.5 之后迭代路线图设计

## 背景

Iteration 0–4.5 已交付确定性核心：Gap Engine、inventory 适配器、本地
`qcov diff`、本地 `qcov policy check`，以及声明式 junit/playwright
`EvidenceMapping`。公开文档仍把 Iteration 5–7 笼统写成「AI 建议层」、
Iteration 8 写成生产证据，缺少拆分计划。

最初白皮书（`QCov_AI_Native_Quality_Evidence_Gap_Engine_Proposal`）定义为：

- Iteration 5：AI Obligation Assistant
- Iteration 6：AI Quality Planner
- Iteration 7：Agentic Quality Loop
- Iteration 8：Production Quality Feedback

并在 Obligation Assistant 与 Planner 之间还有 AI Phase 2（Change Risk Analyzer）。
Iteration 4 后修订插入了 4.5，并要求进入 AI 前先做真实项目验证。

## 决策

采用**方案 B（修订版）**：保留白皮书对 5–8 的语义；在 4.5 后插入显式验证门槛；
把 Change Risk 与映射加固并进 Iteration 5，使 6 及之后保持单职责；将
Iteration 8 视为**核心路线图收官里程碑**，而非产品终点。

原则不变：

> AI proposes. Policy approves. Deterministic engine verifies.

## 序列

```text
已交付: 0 → 1 → 2 → 3 → 4 → 4.5
                 ↓
           [Gate] 真实项目验证
                 ↓
           5  映射加固 + Obligation Assistant + Change Risk
                 ↓
           6  AI Quality Planner（仅此）
           7  Agentic Quality Loop（仅此）
           8  Production Evidence（仅此）
                 ↓
           Post-8 backlog（需单独设计）
```

### Gate（4.5 → 5）

加速 AI 前验证 H1–H4：

1. Testing Obligation 比「需求—测试」追溯更有价值。
2. 初始接入足够快（对齐白皮书 TTFV 目标）。
3. Gap 可解释（为何缺失、对应哪项义务、需要何种证据）。
4. 能发现普通报告掩盖的证据遗漏。

产出：过程记录；必要时小幅 DX / 文档 / 示例修复。
若验证证明必须先扩映射再谈 AI，将该工作作为 **Iteration 5a**（仍不让 AI
成为门禁权威）。

### Iteration 5 — AI 与映射的打包基础

| 块 | 范围 | 主要表面 |
| --- | --- | --- |
| **5a 映射加固** | 将显式 pytest marker 接入评估；按真实项目需要提供有限 identity DX（如有限通配）；映射保持声明式 | config / mapping / 评估路径 |
| **5b Obligation Assistant** | 基于需求等相关上下文提出义务 / 风险 / 建议证据 | `qcov obligation suggest` |
| **5c Change Risk** | 基于本地变更上下文提出受影响义务 / 风险 / 建议证据 | `qcov risk analyze` |

Iteration 5 硬边界：

- AI 输出仅为**提案**，不得写成带权威通过语义的 `QualityEvidence`。
- AI 不得覆盖 `policy check` 或 Gap Engine 判定。
- 不做 inventory → 义务的自动推断。
- 无后续专项设计前，不做 coverage/LCOV 提升为可满足的 `passed` 证据。
- 本迭代不做远程 Git、Web UI、持久化或外部插件 SDK。

### Iteration 6 — AI Quality Planner（纯）

输入：缺失 / 部分覆盖的 gap（及已批准义务）。
输出：下一步最值得采取的验证策略（`qcov plan`）。
以证据收益 vs 执行成本为框架；仍仅为提案。

### Iteration 7 — Agentic Quality Loop（纯）

为 coding agent 提供稳定的机器可读 gap/plan 契约。
可选 `qcov explain`。
闭环形态：消费 gaps → 选择验证 → 执行 → 产出证据 → `qcov check`。
Agent 不得伪造证据或绕过 hard gate。

### Iteration 8 — Production Evidence（纯）

将 runtime / incident / observability 类生产者接入为 inventory（或显式证据），
仍遵守同一协议纪律：生产观察不得在无显式映射 / 证据规则时自动变成 `COVERED`。

**Roadmap Complete through Iteration 8** 表示计划中的核心弧
（缺口 → 变更感知 → 策略 → 映射 → AI 建议/规划/Agent 反馈 → 生产回流）
**已落地**。这**不**表示仓库或产品停止演进。

## Post-8 backlog

实施前需单独批准设计：

- QA for AI 维度（trajectory、tool use、safety、LLM eval）
- Quality BOM（Q-BOM）试验
- Adapter SDK / 超出 built-in registry 的更广语言生态
- 远程 Git 与更深 CI/PR 自动化
- 策略 DSL、维度阈值、路径/通配符豁免
- coverage/LCOV 提升为可满足证据
- inventory → 义务自动推断
- Web UI、数据库持久化、Continuous Quality Control Plane 打包

## 本文档非目标

- 本次修订本身不改协议、CLI 或引擎行为。

- 不承诺日历周次；只定顺序与边界。

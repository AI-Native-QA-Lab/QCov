# QCov 1.0（Iteration 9）正式交付设计

## 1. 目标与基线

Iteration 8 已在 `v0.9.0` 交付：本地 `production-observation` inventory、显式 mapping、时间戳权威和既有 Gap / policy 语义均已发布。QCov 1.0 由 Iteration 9 完成，目标是证明 QCov 能在真实项目中稳定发现普通测试、覆盖率和静态报告没有直接暴露的质量缺口。

本迭代的真实验证项目固定为四个候选项目；1.0 Release Gate 取前三个必需能力，第四个作为额外生态验证：

| 项目 | 验证角色 |
| --- | --- |
| `~/awsomeCode/ai-native-qa-agents` | Python / pytest / coverage |
| `~/awsomeCode/ai4se-demo-project` | Java / Maven / JUnit；JaCoCo 在临时副本中以命令行插件生成 |
| `~/Desktop/AwsomeCode/naodeng.com.cn` | TypeScript / Playwright |
| `~/awsomeCode/ai-test-auditor` | TypeScript / Node / Vitest 额外生态验证 |

四个目标项目只读。测试命令在固定 commit 的临时副本或临时输出目录执行，不在目标项目写入缓存、报告或配置。QCov 的配置、义务、mapping、工件、预期结果和案例说明只写入本仓库的 `examples/case-studies/`、`docs/case-studies/` 与 `docs/process/`。目标项目现有未提交修改必须保留。

## 2. 交付范围

### 2.1 Change → Obligation Impact

新增版本化协议 `qcov.impact/v1` 和本地配置 `QualityImpactConfig`。核心协议继续使用已发布的 `qcov.dev/v1alpha1`，不在 1.0 隐式改名为 `qcov.dev/v1`。配置使用显式 path → obligation mapping：

```yaml
apiVersion: qcov.dev/v1alpha1
kind: QualityImpactConfig
mappings:
  - id: refund-service
    paths: [src/refund/**]
    obligations: [QO-REFUND-001, QO-REFUND-003]
```

输入有两个互斥模式：直接 changed files，或本地 Git 的 `--base <ref> --head <ref>`。命令契约为 `qcov impact --config <project-config> --impact-config <impact-config> [--changed-file <path>]... [--base <ref> --head <ref> --repo <path>] --format json|markdown`；直接模式的 `--repo` 默认取 project config 所在目录，Git 模式必须显式提供或使用同一目录。`qcov affected` 复用相同输入并只渲染受影响义务。`qcov diff` 增加稳定的 `changedFiles` 字段，但仍只负责快照差异。

输出包含 `contractVersion: qcov.impact/v1`、`changedFiles`、`affectedObligations`、`newGaps`、`resolvedGaps` 和 `diagnostics`，并冻结以下最小 JSON 形状：`changedFiles` 是已排序、去重的 `string[]`；`affectedObligations` 是已排序、去重的 obligation ID `string[]`；`newGaps` 与 `resolvedGaps` 是已排序的对象数组，每项为 `{obligationId, status, missingDimensions}`，其中 `newGaps.status`/`missingDimensions` 来自 head、`resolvedGaps.status`/`missingDimensions` 来自 base，`status` 为 Gap Engine 的 `MISSING|PARTIAL|UNKNOWN`，`missingDimensions` 为已排序的质量维度字符串数组；`diagnostics` 是已排序的 `{code, message, path?, severity}` 对象数组，其中 `QCOV-IMPACT-001`、`QCOV-IMPACT-003` 为 error（退出码 4），`QCOV-IMPACT-002` 为 warning（未匹配文件不阻止成功，退出码 0），`QCOV-IMPACT-004` 为 info（退出码 0）。Git 双快照对 head 新增且非 `COVERED` 的义务，或两个快照都存在且状态从 `COVERED` 变为 `MISSING|PARTIAL|UNKNOWN` 的义务生成 `newGaps`；仅对两个快照都存在且状态从 `MISSING|PARTIAL|UNKNOWN` 变为 `COVERED` 的义务生成 `resolvedGaps`。义务从 head 删除不算 resolved gap；其余状态变化保留在 `keyGaps`/诊断中，不伪装成 delta。两个数组均按 `(obligationId, status, missingDimensions)` 排序。直接 changed-files 模式不提供基线评估时，`newGaps` 与 `resolvedGaps` 为空，并返回 `QCOV-IMPACT-004`（`gap delta not assessed`）但保持成功退出；Git 双快照模式才计算 Gap delta。路径统一为仓库相对 POSIX 路径，拒绝绝对路径与 `..`，沿用现有 `**` glob 语义；映射按文件名排序、去重，未匹配文件为 `QCOV-IMPACT-002`，非法输入为 `QCOV-IMPACT-001`，引用不存在义务为 `QCOV-IMPACT-003`。`--changed-file` 不能与 `--base`/`--head` 混用；混用、只提供一侧快照或未提供任何 changed file 时均为 `QCOV-IMPACT-001`，退出码 4。1.0 只实现 path glob；package/module/service/API/component 只能由用户预先展开为显式路径规则，不做源码语义推断、远程 Git 或 AI 权威判定。

`qcov impact` 输出完整协议；`qcov affected` 使用同一输入契约，输出同一 `changedFiles`、`affectedObligations`、`diagnostics`，以及按 obligation ID 排序的 `keyGaps`（元素形状与 `newGaps` 相同）。`keyGaps` 只包含当前输入所评估的受影响义务中状态不是 `COVERED` 的项目；直接模式评估当前 project config，Git 模式评估 head 快照，不计算或暗示 Gap delta。Impact 结果不能绕过 Gap Engine 或改变 policy authority。

实现必须新增 `schemas/qcov.impact-v1.schema.json`，并用 JSON fixture 回归校验上述字段、枚举、排序和 diagnostics severity；Markdown 只是该协议的渲染，不另造字段语义。

### 2.2 Adapter SDK v1 与协议稳定

定义 `qcov.adapter/v1` 的最小稳定契约，放在 `qcov.adapters.sdk`：`ADAPTER_PROTOCOL_VERSION`、`InventoryAdapter`（`name`、`protocol_version`、`scan(path) -> ScanResult`）和从现有 `qcov.adapters.base` 重导出的 `ScanResult`/`ScanDiagnostic`。现有 pytest、JUnit、Playwright、coverage、LCOV、production-observation 适配器保持行为兼容；1.0 新增 JaCoCo XML inventory reader，并增加 `scan.jacoco` 配置键。`diagnostics` 随 `ScanResult` 返回，不另设隐式副作用方法。1.0 只冻结内置/进程内实现契约，不实现第三方插件发现、安装或加载。Adapter 只能发现和规范化观察，不能推断义务、把 PASS/覆盖率提升为业务证据或决定门禁。

冻结并在文档中列出 `qcov.dev/v1alpha1`、`qcov.agent/v1`、`qcov.impact/v1`、`qcov.adapter/v1` 的兼容性约束；核心 `qcov.dev/v1alpha1` 不做破坏性升级。`qcov.agent/v2` 不在 1.0 实现。

### 2.3 真实项目案例包

每个项目在 QCov 中使用相同结构：

```text
examples/case-studies/<project>/
├── README.md
├── README.zh-CN.md
├── metadata.yaml
├── qcov.yaml
├── obligations.yaml
├── mappings.yaml
├── artifacts/
└── expected/
```

`metadata.yaml` 记录只读来源仓库、固定 commit、技术栈、验证日期、工件来源和脱敏/再分发方式。每个案例的公开说明位于 `docs/case-studies/<project>.md` 与 `docs/case-studies/<project>.zh-CN.md`。只保存最小可再分发工件或离线生成脚本，不复制敏感源码。

案例至少包含每项目 5–20 条关键需求、10–50 条 Testing Obligation。每条 obligation 的 `source.ref` 指向固定 commit 中的 README、需求文档、API 契约或测试约定；不得凭空编写无来源义务。案例对比原有测试报告、覆盖率、静态分析/质量门禁和 QCov 的 Gap / Impact / Policy 输出。

### 2.4 文档与上手

README 和公开文档继续中英文配对。1.0 必须包含：

- Python 3.11+ 支持范围、用户安装与源码开发安装；
- 5 分钟首个 `qcov gaps` 运行和预期输出；
- `scan` → `map preview` → `gaps` → `impact` → `policy check` 命令导览；
- 配置文件、案例目录和报告解释；
- Python、Java、TypeScript 的上手入口；
- Python 版本、文件缺失、配置错误、未映射 inventory 的故障排查；
- 明确测试 PASS、覆盖率 PASS、Adapter 输出和 Agent 提案都不等于业务义务已证明。

README 保持入口简洁；详细配置、案例和排障放在 `docs/en|zh-CN/` 与 `docs/case-studies/`。每条公开命令必须在干净环境中实际运行并记录结果。Time to First Value 从干净临时副本完成 QCov 安装开始，到第一次成功输出 Gap 报告结束；记录 Python/Node/Maven 版本、机器、命令和墙钟秒数。

## 3. Release Gate

只有全部条件满足才可标记 QCov 1.0：

1. 至少三个真实项目完成验证，并覆盖 Python/pytest/coverage、Java/JUnit/JaCoCo、TypeScript/Playwright；本迭代固定的三个必需案例为 `ai-native-qa-agents`、`ai4se-demo-project`、`naodeng.com.cn`，`ai-test-auditor` 为额外案例；
2. 合计至少 30 条真实 Testing Obligation；
3. 每个案例 Time to First Value ≤ 10 分钟；
4. 至少发现一类普通 Test/Coverage/Static Report 没有直接暴露的关键或此前未知缺口，且缺口可解释；
5. 记录 false-gap rate（人工复核为误报的 Gap 数 / 抽样 Gap 总数）、Gap → Added Verification Conversion（已补充并成功映射的原缺口数 / 可行动缺口数）、Developer/QA Acceptance（至少两名开发/QA 对可解释性和行动价值的独立结论）；
6. Impact、Adapter、协议回归测试及既有 Gap / policy 测试通过；
7. 双语 README、Getting Started、案例文档和所有示例命令通过文档检查及实际执行；
8. `pytest`、`ruff check .`、`mypy qcov`、`python -m build`、`git diff --check` 全部通过。

## 4. 非目标

1.0 不实现 AI Obligation Discovery、AI Change Impact、`qcov explain --ai`、AI Suggested Plan、`qcov.agent/v2`、自动测试执行、远程 Git、外部插件加载、Web UI、持久化、自动义务推断、策略 DSL、维度阈值、通配符/路径豁免或 coverage/LCOV promotion。它们分别属于 1.5、2.0 或后续单独设计。真实项目验证若因 Maven/Node/Python 依赖、浏览器、网络或权限无法运行，必须标记为 `blocked`，不能计入 Release Gate。

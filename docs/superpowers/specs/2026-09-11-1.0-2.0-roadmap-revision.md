# QCov 1.0 → 1.5 → 2.0 路线图修订设计

## 背景

Iteration 0–7 已交付确定性缺口引擎、本地映射、策略、提案、规划与 Agent 助手；Iteration 8 已有独立的离线生产观测设计。旧路线把 Iteration 8 描述成核心弧收官，无法表达接下来先验证真实价值、再扩大 AI 能力的产品节奏。

## 决策

1. Iteration 8 保持为离线、显式映射的 production-observation 基础，不因本修订扩大实现范围，也不宣称路线图完成。
2. Iteration 9 开启 QCov 1.0（Find the Gap）：真实项目验证、确定性的 Change → Obligation Impact、Adapter SDK v1 与协议稳定性。
3. QCov 1.0 的 release gate 固定为至少 3 个真实项目、30 条真实 Testing Obligation、3 种技术栈、首次价值时间不超过 10 分钟，并记录普通报告未直接暴露的可解释缺口。
4. QCov 1.5（Understand & Plan）才引入 AI Obligation Discovery、AI Change Impact、AI Gap Explanation、AI Suggested Plan 与 Quality Evidence ROI；AI 仅能理解、建议、解释与规划。
5. QCov 2.0（Close the Loop）才设计 `qcov.agent/v2`、candidate evidence 验证、QA for AI、生产质量反馈与 Quality BOM；Agent 永不能自证 `COVERED`。

## 不变边界

- `qcov.dev/v1`、`qcov.agent/v1` 的既有语义不因路线图文字改变。
- Adapter 不是 evidence authority；JUnit PASS、覆盖率与 Agent 输出都不能绕过显式 mapping、Gap Engine 或 policy。
- 不在本次文档修订中实现 Adapter SDK、impact CLI、远程 Git、外部插件、Web UI、持久化、自动义务推断、策略 DSL、维度阈值或 coverage/LCOV promotion。

## 文档影响

更新双语公开 `roadmap.md` 与 `requirements.md`、仓库 `AGENTS.md`、Iteration 8 的现有设计/计划表述，并添加本设计、实施计划和中文过程记录。文档测试必须防止恢复“Iteration 8 即路线图完成”的过期说法。

# Iteration 4.5 显式义务映射设计

## 目标

Iteration 4.5 补上 ADR 0003 延后的首次价值闭环：用**声明式、本地、确定性**的
映射，把选定的 inventory observation 提升为可进入 Gap Engine 的
`QualityEvidence`。

映射只表达「作者明确声明的关系」；不根据测试名、包名、行覆盖率或报告结构
**推断**义务。映射不改变 `InventoryRecord` 本身，也不削弱「只有 `passed` 才能
满足 required evidence」的既有规则。

本迭代要让 `gaps` / `check` / `report` / `policy check` 在使用 `--config` 时，
能把「扫描到的 JUnit/Playwright 结果 + 映射文件」与可选的手写 evidence 一并评估，
从而减少纯手工抄写证据的成本，同时保持可审计。

## 非目标

- 通配符、glob、正则匹配 inventory `identity`
- 根据测试名 / 类名 / 路径自动推断 `obligationRef`
- 将 coverage.py / LCOV 的行覆盖观察提升为可满足义务的 `passed` 证据
- 外部插件、远程 Git、数据库、Web UI、AI
- 改变 `diff` 的「只比较协议文件快照」语义（见后续候选）
- 默认把映射结果写回磁盘覆盖手写 evidence
- 策略 DSL、维度阈值、路径豁免（仍属后续）

## 现状与缺口

今天的流水线是：

```text
scan.* 报告 ──► InventoryScanner ──► InventoryRecord ──► scan 摘要后丢弃记录
手写 QualityEvidence YAML ─────────────────────────────► Gap Engine
pytest.mark.qcov ──► QualityEvidence(status=unknown) ──► 仅计入 scan 数量
```

因此：

1. `ScanReport` 只保留 adapter 摘要，**不保留** inventory 载荷，映射无处取材。
2. 通用导入永远进不了 `gaps` / `check` / `report` / `policy check`。
3. pytest marker 虽已带 `obligation.ref`，但状态固定为 `unknown`，且未进入评估路径。
4. 现 CLI 在 `--config` 下要求「至少一个 evidence 文件」，与「仅靠映射产物评估」冲突。

4.5 打通 **junit / playwright inventory → 显式映射 → QualityEvidence**，并放宽
config 证据来源门槛（见 CLI）。pytest marker 与 coverage/LCOV 见「范围边界」。

## 架构

```text
qcov.yaml
  obligations[] ──► TestingObligation
  evidence[]    ──► QualityEvidence（手写，可为空列表）
  scan.*        ──► InventoryRecord[]
  mapping[]     ──► EvidenceMapping
                         │
                         ▼
              mapping engine（纯函数）
                         │
                         ▼
         QualityEvidence[]（映射产物，内存合并）
                         │
         ┌───────────────┴───────────────┐
         ▼                               ▼
   与手写 evidence 去重合并         map preview 报告
         ▼
   既有 Gap Engine / policy check
```

边界：

| 组件 | 职责 |
| --- | --- |
| `qcov.models.protocol` | 新增严格的 `EvidenceMapping` 协议模型与 Schema |
| `qcov.models.config` | `QCovConfig.mapping`；`ResolvedPaths.mapping`；`resolve_paths` |
| `qcov.engine.scan` | 保留完整 `InventoryRecord` 供映射使用（摘要 API 可并存） |
| `qcov.engine.mapping` | 纯函数：records + mappings → `QualityEvidence` + diagnostics |
| `qcov.cli.app` | `--config` 评估路径合并映射产物；放宽 evidence 门槛；`qcov map preview` |
| Gap / policy | **不改**判定语义，只多接收合并后的 evidence 列表 |

## 协议：`EvidenceMapping`

沿用 `qcov.dev/v1alpha1`，新增 kind：

```yaml
apiVersion: qcov.dev/v1alpha1
kind: EvidenceMapping
metadata:
  id: refund-import-mapping
defaultTimestamp: "2026-09-08T00:00:00+08:00"
mappings:
  # 示意结构；fixture 真实 identity 见「示例约定」
  - from:
      producer: junit
      identity: "refund.api::refund_is_accepted"
    to:
      obligationRef: QO-REFUND-001
      dimension: behavior
      type: api_test
    timestamp: "2026-09-08T12:00:00+08:00"   # 可选；与 from/to 同级
  - from:
      producer: playwright
      identity: "tests/refund.spec.ts::refund > shows confirmation [chromium]"
    to:
      obligationRef: QO-REFUND-001
      dimension: behavior
      type: e2e_test
      evidenceId: QE-MAP-REFUND-E2E-001
```

### 字段规则

- `metadata.id`：非空。多个 mapping 文件之间不得重复该 id。
- `defaultTimestamp`：必填、带时区的 ISO 8601。映射产物的
  `execution.timestamp` **只**取显式时间戳（见下），禁止读文件 mtime 或系统时钟。
- `mappings`：至少一个条目；禁止额外字段。
- `from.producer`：模型层使用 `Literal["junit", "playwright"]`（与
  `InventoryRecord.producer` 一致）。非法值在加载时失败，错误码
  `QCOV-SCHEMA-001`（**不**另设 `QCOV-MAP-004`）。
- `from.identity`：与对应 adapter 发出的 `identity` **逐字相等**；不做规范化、
  不匹配路径别名。Playwright 使用 ASCII ` > ` 连接 suite/spec（与
  `PlaywrightAdapter` / 现有测试一致），**不是** Unicode `›`。
- `to.obligationRef` / `dimension` / `type`：必填；`dimension` 必须是既有
  `QualityDimension`；`type` 为非空字符串。映射层不预加载义务文件做存在性校验。
- `to.evidenceId`：可选。缺省时确定性生成为：

  `QE-MAP-{producer}-{stable_token(identity)}-{obligationRef}-{dimension}-{type}`

  其中 `stable_token` 为固定算法（实现锁定并测试）。须纳入 **obligationRef 与
  type**，以便同一 `(producer, identity)` 合法映射到不同目标时 id 不碰撞。
- 条目级 `timestamp`：可选，与 `from` / `to` **同级**；若存在必须带时区，并作为
  该条的 `execution.timestamp`；否则用 `defaultTimestamp`。

同一文件内允许：

- 同一 `(producer, identity)` 映射到**不同** `(obligationRef, dimension, type)`；
- 不同 inventory 映射到同一义务维度。

禁止：

- 同一文件内重复的 `from`+`to` **五元组**
  `(producer, identity, obligationRef, dimension, type)`；
- 同一评估中重复的 `evidenceId`（含缺省生成与显式指定、跨 mapping 文件）→
  `QCOV-MAP-002`；
- 多个 mapping 文件之间重复的 `metadata.id` → `QCOV-MAP-007`。

## 状态翻译

映射引擎把 inventory `status` 译为 `execution.status`，采用**保守、固定**表：

### junit

| inventory status | execution.status |
| --- | --- |
| `passed` | `passed` |
| `failed` | `failed` |
| `skipped` | `skipped` |
| 其他 | `unknown`（并发出 `QCOV-MAP-003`，仍生成 evidence） |

### playwright

| inventory status | execution.status |
| --- | --- |
| `expected` | `passed` |
| `unexpected` | `failed` |
| `skipped` | `skipped` |
| `flaky` | `failed`（保守：不稳定不视为满足） |
| 其他 | `unknown` + `QCOV-MAP-003` |

只有译为 `passed` 的条目能让 Gap Engine 将该维度标为 `COVERED`。失败/跳过/
unknown 会进入 observed evidence，但**永不**满足要求。

注意既有 `gaps.py` 语义：若某维度的匹配 evidence 中**任意一条**为
`unknown`，该维度即为 `UNKNOWN`（即便另有 `passed`）。因此 `QCOV-MAP-003`
产物可能把本可 COVERED 的维度拉成 UNKNOWN；作者应修正 inventory status 或
避免映射异常条目。

## 匹配与歧义

对每条 mapping，在 inventory 中查找 `producer` 与 `identity` 均相等的记录：

- **0 条**：发出 `QCOV-MAP-001`，不生成 evidence。
- **恰好 1 条**：物化一条 `QualityEvidence`。
- **多于 1 条**：发出 `QCOV-MAP-005`（歧义），**不**物化——避免一条 mapping
  产出多条同 id 证据或静默重复。作者须先清理报告或收紧 identity。

## 映射产物形状

```yaml
apiVersion: qcov.dev/v1alpha1
kind: QualityEvidence
metadata:
  id: <evidenceId>
obligation:
  ref: <obligationRef>
evidence:
  dimension: <dimension>
  type: <type>
producer:
  name: <inventory.producer>          # junit | playwright
  adapter: qcov-mapping
execution:
  status: <translated>
  timestamp: <effective timestamp>
artifact:
  path: <stable relative path>
confidence:
  deterministic: true
  reproducible: true
```

`artifact.path` **不得**写入本机绝对路径。映射引擎在物化时把
`InventoryRecord.artifact_path` 转为相对 **配置文件目录**（`qcov.yaml` 所在目录）
的稳定相对路径（POSIX 风格）；若无法相对化，则使用原 inventory 中的 basename
并附加 `QCOV-MAP-006` diagnostic。禁止依赖进程 cwd。

`producer.adapter` 固定为 `qcov-mapping`，标明证据来自映射层而非手写。

## 配置契约

```yaml
apiVersion: qcov.dev/v1alpha1
kind: QCovConfig
obligations:
  - ../refund/obligation.yaml
evidence: []                          # 允许为空，见 CLI
mapping:
  - mappings/*.yaml
scan:
  junit:
    - junit.xml
  playwright:
    - playwright.json
```

- `mapping`：相对配置文件的路径/glob；解析、排序、去重与 `obligations` /
  `evidence` 相同，结果进入 `ResolvedPaths.mapping`。
- 配置了 `mapping:` 但 glob 未解析到任何文件 → `QCOV-CONFIG-001`。
- 未写 `mapping:` 键 → 行为与 Iteration 4 完全一致（含「至少一个 evidence 文件」）。
- 已配置的 junit/playwright 文件缺失 → 非致命 `QCOV-SCAN-001`（与现 scan 一致）。

## CLI 契约

### 评估路径合并（主路径）

当 `gaps` / `check` / `report` / `policy check` 使用 `--config` 时：

1. 解析 obligations、evidence、mapping、scan 路径。
2. **门槛（相对 Iteration 4 的变更）**：
   - 仍要求恰好一个 obligation 文件；
   - 若配置含非空 `mapping:` 解析结果：允许 `evidence:` 为空；
   - 若未配置 `mapping:`：仍要求至少一个 evidence 文件（旧行为）；
   - 若配置了 `mapping:` 且 `evidence:` 为空：继续执行；映射后 evidence
     总数可以为 0（义务将按既有空观测规则变为 UNKNOWN/MISSING）。
3. 对已配置的 junit/playwright 执行 inventory scan，**保留 records**。
4. 加载全部 `EvidenceMapping`：先按**解析后的 mapping 文件路径**升序，再按文件内
   条目顺序应用；并校验各文件 `metadata.id` 唯一。
5. 物化映射产物；收集 `QCOV-MAP-*` / 沿用的 scan diagnostics。
6. 与手写 evidence 合并：任一 `metadata.id` 冲突 → 致命 `QCOV-MAP-002`，退出码 4。
7. 将合并列表交给既有 evaluator / policy。
8. **diagnostics 表面化**：凡本次评估应用了 mapping，JSON 根对象在既有
   `results` 之外增加 `mappingDiagnostics`（对象数组，含 `code`、`message`、
   可选 `mappingId` / `producer` / `identity`；按 `code`、`message` 稳定排序）。
   Markdown 增加「Mapping diagnostics」小节（`--locale` 可本地化标题，码与
   identity 不翻译）。`policy check` 的 JSON/Markdown 同样附加该块，不改变
   `decision` 语义。未使用 mapping 时不出现该字段/小节。

仅使用 `--obligation` / `--evidence`（无 `--config`）时**不**应用映射。

### 新增：`qcov map preview`

```text
qcov map preview --config CONFIG [--format markdown|json] [--locale en|zh-CN]
```

只读预览，不写磁盘。

**JSON**（稳定英文键，禁止绝对路径）：

```json
{
  "mappingIds": ["refund-import-mapping"],
  "evidence": [
    {
      "evidenceId": "QE-MAP-...",
      "obligationRef": "QO-REFUND-001",
      "dimension": "behavior",
      "type": "api_test",
      "executionStatus": "passed",
      "producer": "junit",
      "artifactPath": "junit.xml"
    }
  ],
  "diagnostics": []
}
```

- `mappingIds`：升序。
- `evidence`：按 `evidenceId` 升序。
- `diagnostics`：按 `code`、`message` 升序。

**Markdown**：列出同上事实；支持 `--locale en|zh-CN`。

退出码：

| 退出码 | 含义 |
| --- | --- |
| 0 | 预览成功（允许存在未匹配等非致命 diagnostics） |
| 4 | 配置/映射协议无效，或 evidence id 冲突，或 mapping 文档 id 重复 |

## 错误码

| 码 | 何时 | 致命？ |
| --- | --- | --- |
| `QCOV-CONFIG-001` | 无效配置；或已声明的 mapping glob 未解析到文件 | 是 |
| `QCOV-SCAN-001` | 既有：报告缺失/损坏 | 否 |
| `QCOV-SCHEMA-001` | 既有：mapping 文件 schema/模型校验失败（含非法 producer） | 是 |
| `QCOV-MAP-001` | `(producer, identity)` 在 inventory 中无匹配 | 否 |
| `QCOV-MAP-002` | evidence `metadata.id` 冲突 | 是 |
| `QCOV-MAP-003` | inventory status 不在翻译表内，已按 `unknown` 物化 | 否 |
| `QCOV-MAP-005` | 多个 inventory 记录匹配同一 `(producer, identity)` | 否 |
| `QCOV-MAP-006` | artifact 无法相对化到配置目录，已降级为 basename | 否 |
| `QCOV-MAP-007` | EvidenceMapping `metadata.id` 重复 | 是 |

## 范围边界

### 本迭代包含

- `EvidenceMapping` 模型 + JSON Schema
- config `mapping` 与 `ResolvedPaths.mapping`
- scan 保留 inventory records 的内部 API
- 纯映射引擎、状态翻译、歧义处理、相对 artifact 路径
- `--config` 评估路径合并与 diagnostics 表面化
- 放宽「mapping 存在时可无手写 evidence」
- `qcov map preview`
- `examples/imported-reports` 增加最小 mapping，使 junit 和/或 playwright
  经映射后进入 `gaps` 并可解释
- 配对 `docs/en/mapping.md` 与 `docs/zh-CN/mapping.md`，更新 README /
  roadmap / requirements 交叉链接
- 过程记录与 TDD 证据
- **真实接入验证（过程交付）**：关闭本迭代前，在 `docs/process/` 记录一次
  对本仓库（或外部样例仓）的接入观察——至少含：配置 mapping 的大致耗时、
  `map preview` / `gaps` 是否可解释、相对「仅看 junit/覆盖率报告」多看出的缺口。
  不要求改产品核心协议；验收以过程记录为准，可与实现同一 PR 或紧随其后。

### 本迭代明确不做

| 项 | 原因 |
| --- | --- |
| coverage.py / LCOV → `passed` | 行覆盖不能证明业务义务；producer 白名单在模型层拒绝 |
| pytest marker 自动进入 gaps | marker 状态恒为 `unknown`；另需关联设计 |
| `diff` 感知 mapping | 两端重跑 scan+mapping，协议面更大 |
| identity glob | 与 Iter 4 豁免「仅精确匹配」一致 |
| 写回 evidence 目录 | 避免静默改仓库；preview 足够 |

### 与 ADR 0003 的关系

ADR 0003 **仍然有效**：默认导入仍是 inventory。本设计是 ADR 所预见的
「future explicit mapping layer」的落地，不推翻「无映射则不构成证据」。

## 确定性与信任边界

- 不执行项目测试，不 import 项目代码，不访问网络时钟。
- 时间戳仅来自 mapping 文件中的显式字段。
- identity 匹配逐字相等；adapter 变更 identity 格式属破坏性变更，须升版本说明。
- 映射引擎不读取义务文件内容做「是否值得映射」的智能判断。
- JSON 键、错误码、producer 名保持英文；报告禁止本机绝对路径。

## 测试策略

按 TDD，至少覆盖：

1. **模型**：合法 mapping；缺 timestamp；非法 producer → schema 失败；重复
   evidenceId；条目级 timestamp；额外字段拒绝。
2. **引擎**：junit/playwright 状态翻译；未匹配 → `QCOV-MAP-001`；歧义 →
   `QCOV-MAP-005`；id 冲突 → `QCOV-MAP-002`；未知 status → `unknown` +
   `QCOV-MAP-003`；缺省 id 含 obligationRef/type；artifact 相对化。
3. **配置**：glob 解析；mapping glob 空匹配 → config error；`evidence: []` +
   有效 mapping 可评估。
4. **CLI**：`map preview` JSON 键/排序/中英文 Markdown；`gaps --config` 合并后
   可解释且含 `mappingDiagnostics`；无 `mapping:` 时回归不变；直接
   `--obligation/--evidence` 不隐式映射。
5. **示例**：imported-reports 文档命令可复现。

最终门禁：`pytest`、`ruff check .`、`mypy qcov`、`python -m build`、
`git diff --check`。

## 验收标准

1. 无 mapping 时，既有命令与测试行为不变。
2. 有 mapping 时，作者能把 fixture 中的 junit（或 playwright）条目显式绑到义务
   维度，并在 `gaps` 中看到对应 evidence id 与状态。
3. `map preview` 能在不写盘的情况下解释将生成什么、哪条未匹配/歧义。
4. `from.producer: coverage.py`（或 lcov）在模型/schema 加载阶段被拒绝。
5. 文档明确：QCov 不是行覆盖率工具；映射是声明，不是推断。
6. 过程记录含一次真实接入验证观察（见上）。
